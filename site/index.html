For Siemens TIA Portal V20 and CODESYS V3.5

TIA Portal projects,
as plain text.

rung keeps a TIA Portal project and a folder of text files in sync, in both directions. Write SCL in VS Code, Zed or Neovim, review every change in git, and let coding agents work on the same files you do.

Quickstart Source on GitHub
01

Both sides stay current

Start rung watch and leave it running. When you save a file, rung imports it through Openness, compiles the block and writes TIA's version back, so the file always matches the project. Change something in TIA Portal and the file follows within a couple of seconds. If both sides changed, rung merges: SCL line by line, LAD and FBD network by network, so two people working on different networks of one block both keep their change. A real conflict stops and shows you both sides.

02

An editor that knows SCL

The language server completes variables and members, jumps to definitions through DBs, UDTs and FB instances, finds references and renames safely. Compile errors from TIA Portal land on the line they belong to. There are extensions for VS Code and Zed, and a short config for Neovim. TwinCAT and plain IEC 61131-3 files work too.

03

Agents edit files, not the project

Claude Code, Codex and Cursor change the text files like any other code, and rung carries the change into TIA Portal. A small MCP server gives them what the files can't: sync status, compile results, cross references and the test runner. The Claude Code plugin adds skills for the sync workflow, for keeping away from safety code, and for reviewing a change before it goes in. 

$ rung mcp
rung_status        rung_sync
rung_diagnostics   rung_compile
rung_find_usages   rung_graph
rung_explain       rung_diff
rung_test          rung_live_read
…and a few more
04

Tests for blocks

Describe a few scan cycles in YAML and rung test runs them on an offline simulator for SCL, LAD, FBD, STL and structured text, with virtual time, IEC timers, edge detection and common system instructions. No PLC, PLCSIM or TIA Portal needed, so it runs on any CI runner, Linux too, and prints JUnit. 

# tests/motor.test.yaml
block: Fx_Motor
cases:
  - name: starts and latches
    steps:
      - set: { Start: true, SpeedSetpoint: 1500 }
      - cycle: 1
      - expect: { Running: true, SpeedOut: 1500 }

Careful by default

  • It talks to TIA Portal only through Siemens' Openness API and never opens project files itself.
  • It never downloads by itself. A person starts every download, types the PLC name and allows each risky question TIA asks by name. rung's agent tools only prepare a download for a person. Live values come from the S7-1500 Web API, read only.
  • Failsafe, know-how protected, system and GRAPH blocks and instances of library types are exported for reading and never imported.
  • Imports run inside a TIA transaction and check the block's revision first. If someone changed it in the meantime, rung stops.
  • Deleting a file never deletes a block. You confirm that yourself with rung confirm-delete.

Requirements

Windows with TIA Portal V20 and the Openness option (your user in the Siemens TIA Openness group), or with CODESYS V3.5. From Linux or macOS, a Windows PC with it over ssh.

Status

Pre-alpha, no release yet. Tested against real TIA Portal V20, S7-PLCSIM and CODESYS V3.5 on generated projects; the end-to-end suites pass. V21 builds but is untested.
